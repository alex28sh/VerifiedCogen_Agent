You remember the following aspects of Nagini:

1. Nagini DOES NOT SUPPORT some Python features as list comprehensions (k + 1 for k in range(5)), as double inequalities (a <= b <= c).
Instead of double inequalities it's customary to use two separate inequalities (a <= b and b <= c).

For example, for the following code snippet and error
"
    Invariant(0 <= i <= len(numbers))
"
"
    Translation failed
    Not supported: (0 <= i <= len(numbers))
"
the reason is not supported double inequality and it should be rewritten with 2 inequalities.

2. Inside invariants/postconditions only calls to pure functions, builtins are supported.
the following code snippet cause error
"
def inc(i: int) -> int:
	return i + 1

...
        Invariant(inc(1) == 10)
"
"
Translation failed
Invalid program: purity.violated
"
Because, inc should be annotated @Pure to be called inside invariant.

3. Nagini requires special annotations for working with lists `Acc(list_pred(..))`. You can use these constructs only inside `Invariant`,
anywhere else you should not use `Acc()` or `list_pred()`:
"
    while i < len(numbers):
        Invariant(Acc(list_pred(numbers)))
"

"
Verification failed
 Errors:
 The precondition of function len might not hold. There might be insufficient permission.
"

or
"
Verification failed
Errors:
The precondition of numbers[i] might not hold. There might be insufficient permission
"
can indicate the absence of this invariant.

4. Nagini contains `Forall` and `Exists` constructs that can be used in invariants. First argument of Forall/Exists is typically a type (i.e `int`),
second argument is a lambda. `Forall(type, lambda x : a)` denotes that assertion `a` is true for every element `x` of type `type`.

Also, for some Forall statements, that require resource-intensive proofs, you could need to add triggers to invariants/assertions/preconditions:
"
An advanced version Forall(iterable, lambda x: (a, list_of_triggers))
allows to specify when the forall quantifier should be instantiated by the underlying SMT solver.
list_of_triggers is a list of lists of trigger expressions;
as an example, with [[add(x, y)]] the quantifier will be instantiated
if the SMT solver either sees the pattern add(x, y).

Usually, some syntactic inconsistencies when writing triggers can cause errors
"
    Invariant(Forall(int, lambda i: not (((0) <= (i)) and ((i) < (len(numbers)))) or ((psum(0, i + 1, numbers)) == (psum(0, i, numbers) + numbers[i])), [[psum(0, i + 1, numbers)]]))
"
causes
"
    Translation failed
    Type error: Too many arguments for "Forall"
"
because the pair condition, [[triggers]] wasn't wrapped in brackets like (condition, [[triggers]])
