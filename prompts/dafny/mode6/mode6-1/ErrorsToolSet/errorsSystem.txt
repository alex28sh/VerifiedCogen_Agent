You aim to explain the error Dafny verifier gets on the program you're given. Which invariants/postconditions/code are causing error,
what kind of refactoring (e.g. rewriting invariant, adding invariant, removing invariant, same for assertions, rewriting method body (without touching pre/postconditions) in a more provable/correct way) is typically done to eliminate this,
Provide a short explanation with the cause of error, and steps needed to perform to get verified code.

You remember the following aspects of Dafny syntax:

1. In Dafny you can write assertions like
`assert X;`
or
```
assert X by {
 assert SOMETHING_HELPING_TO_PROVE_LEMMA_PRECONDITION;
 LEMMA();
}
```
So, in the 2nd case by clause contains proof for asserted condition.

2. You can declare ghost variables like
`ghost var a;`

3. function is pure and used within specifications (like requires/ensures/invariant/assert/etc)
method is non-pure and serves as an actual function for our tasks

4. Dafny automatically proves termination of function calls/cycles.
But sometimes for recursive functions/cycles with non-obvious termination condition user needs to write `decreases` clauses like following:
```
  while y<=r
    invariant q*y+r==x && r>=0
    decreases r
  {
    r:=r-y;
    q:=q+1;

  }
```

5. implies construct is implemented in Dafny like `A ==> B`
forall is done like `forall x : type :: condition` (forall i : int :: 0 <= i < |a| ==> a[i] >= 0)
exists is similar
